5 = 5. Token Rotation Race — Concurrent Requests Cause Forced Logout
session.php:206-222 | CWE-367


if (time() - $rotatedAt > TOKEN_ROTATION_INTERVAL) {
    $rotateStmt = $pdo->prepare(
        'UPDATE sessions SET session_token_hash = :new_hash ... WHERE session_token_hash = :old_hash'
    );
No SELECT ... FOR UPDATE, no transaction. Two tabs sending requests simultaneously during the rotation window: both read the session (both valid), one wins the UPDATE, the other's cookie now references a token hash that no longer exists in the DB. Next request from the losing tab → unexpected logout.

An opponent can weaponize this: send two simultaneous requests to any authenticated page during the rotation window to force-logout the victim.


6. Unbounded Nonce Generation — transfer.php GET Not Rate-Limited
transfer.php:173 | CWE-400

Every GET to transfer.php inserts a row into pending_transfers. Unlike every other authenticated page (dashboard, profile, transactions), transfer.php does not call checkAndRecordPageViewAttempt. An attacker with a session can flood the table with unbounded nonce rows (cleanup only runs every 5 minutes, rows live ~70 minutes). At 100 req/sec, that's 420,000 rows before cleanup.

7. Loose Comparison on PDO Exception Code — Type Juggling
auth.php:111, functions.php:509 | CWE-843


if ($e->getCode() == 23000) {
PDOException::getCode() returns a string SQLSTATE ('23000'). The loose == comparison happens to work because PHP coerces '23000' == 23000 to true. But this is a type juggling fragility — if the SQLSTATE were ever a non-numeric string, the behavior would be wrong. Industry practice (PSR, static analysis tools) flags all == in security-sensitive code. Should be === '23000'.

10. No open_basedir Restriction
Dockerfile:57-71 | CWE-22

PHP can read any file on the container filesystem. If a code execution vulnerability is found, the attacker can read /etc/passwd, /proc/self/environ (revealing env vars including DB_PASS and HMAC_SECRET), or Apache config files.


open_basedir = /var/www/html:/var/www/uploads:/tmp
Would restrict PHP file operations to only the directories it needs.

11. No SRI on External Resources
header.php:25 | CWE-829, OWASP A08


<link href="https://fonts.googleapis.com/css2?family=Inter..." rel="stylesheet">
Google Fonts CSS loaded without Subresource Integrity. If the CDN is compromised or DNS is hijacked, an attacker can inject arbitrary CSS (CSS keyloggers that exfiltrate input values character-by-character via background: url()). Self-hosting the font eliminates this entirely.

Note: standard SRI on Google Fonts is impractical (they serve different CSS per User-Agent), which is exactly why self-hosting is the recommended fix.


14. captcha.php Has No Rate Limiting
captcha.php | CWE-400

No authentication required. No rate limit. Each request:

Creates a GD image (CPU cost)
Starts/writes a PHP session file (disk I/O)
Returns 200 with a PNG
An attacker can DoS by flooding captcha.php with thousands of requests. Should require the same IP-based rate limiting as search.

16. sanitizeOutput Applied to Database Log Data

sanitizeOutput calls htmlspecialchars — an HTML output encoding function applied to a string going into the database. A search for O'Reilly gets stored as O&#039;Reilly in activity_log.page. This corrupts forensic data. HTML encoding belongs at the output layer, not the storage layer.

17. TLS Cipher Suite Too Broad
apache.conf:22


SSLCipherSuite HIGH:!aNULL:!MD5:!3DES
HIGH includes ciphers like AES128-SHA (no forward secrecy) and CAMELLIA (uncommon, less audited). Mozilla's "Modern" profile recommends:


ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384
This ensures forward secrecy (ECDHE) and authenticated encryption (GCM) only.

18. No HSTS preload Directive
security_headers.php:25, apache.conf:26


Strict-Transport-Security: max-age=31536000; includeSubDomains
Missing preload. Without it, the very first visit to the site (before HSTS caches) is vulnerable to SSL stripping. With preload, browsers will refuse HTTP before the first visit even happens (requires submission to hstspreload.org).

19. No upgrade-insecure-requests in CSP
security_headers.php:30

Missing upgrade-insecure-requests directive. If any resource is accidentally referenced via http://, the browser won't auto-upgrade it. Adding this directive provides defense-in-depth.

20. image.php — No Cache-Busting on Profile Update
image.php:44


header('Cache-Control: max-age=86400, private');
Profile images are cached for 24 hours. When a user updates their profile image, old images persist in browser caches. Not a direct security issue, but if someone's account is compromised and the attacker changes the profile picture to something offensive, the victim sees the old image for 24 hours after the attacker's image is removed. Use no-cache with ETag, or include a version hash in the URL.
